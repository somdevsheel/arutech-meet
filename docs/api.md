# API

Full interactive contract: run the API and open `/docs` (Swagger UI, generated by `@nestjs/swagger` from
the live controllers in `apps/api/src/main.ts`). This document is an index, not a duplicate of it.

Base path: `/api/v1` (health check lives outside the prefix, at `/health`).

## Auth (`/auth`) — public except `/auth/me`

| Method | Path | Notes |
|---|---|---|
| POST | `/auth/register` | Argon2 hash, creates first session, returns tokens |
| POST | `/auth/login` | Rate-limited 5/min |
| POST | `/auth/refresh` | Rotates the refresh token; reuse of a stale token revokes the session |
| POST | `/auth/logout` | Revokes the session tied to the given refresh token |
| GET | `/auth/me` | Returns the JWT-derived identity (id/email/systemRole) |

## Users (`/users`)

| Method | Path |
|---|---|
| GET / PATCH | `/users/me` |
| GET | `/users/me/sessions` (active device/session list) |
| GET | `/users/:id` (public profile) |

## Organizations (`/organizations`)

`POST /organizations`, `GET /organizations` (mine), `GET /organizations/:id`,
`POST /organizations/:id/members`.

## Meetings (`/meetings`)

| Method | Path | Auth | Notes |
|---|---|---|---|
| POST | `/meetings` | required | create instant/scheduled/recurring |
| GET | `/meetings` | required | meetings I own or participate in |
| GET | `/meetings/:code` | public | preview only (title, password-required flag) |
| PATCH | `/meetings/:id/settings` | owner/`meeting.settings.update` | |
| POST | `/meetings/:id/end` | owner/`meeting.end` | ends the LiveKit room too |
| POST | `/meetings/:code/join` | required | authenticated join |
| POST | `/meetings/:code/join-as-guest` | public | guest join (name required) |
| POST | `/meetings/:id/participants/:participantId/token` | required | reissue a LiveKit token (self, or a moderator on someone else's behalf) |

`join`/`join-as-guest` return `{ status: "WAITING" | "ADMITTED", livekitToken, livekitUrl, ... }` — a
token is present only when `ADMITTED`. See `docs/webrtc.md`.

## Participants (`/meetings/:meetingId/participants`)

`GET /` (roster), `GET /waiting-room`, `POST /:id/admit`, `POST /:id/deny`, `POST /:id/mute`,
`POST /:id/disable-camera`, `POST /:id/remove`, `POST /:id/promote-co-host`. All require the caller to
hold the corresponding capability from `packages/types/src/permissions.ts` — see `docs/security.md`.

## Chat (`/meetings/:meetingId/chat`)

`GET /messages?cursor=` — paginated history. Sending a message is WebSocket-only
(`WS_EVENTS.CHAT_MESSAGE`) — see `docs/realtime.md`; there is deliberately no REST "send message"
endpoint since delivery must be realtime.

## LiveKit webhook (`/livekit/webhook`)

Server-to-server only, authenticated by LiveKit's webhook signature (not a user JWT) — see
`apps/api/src/livekit/livekit-webhook.controller.ts` and `docs/webrtc.md`.

## Not yet exposed as REST (schema + service interfaces exist; see docs/roadmap.md)

Classes/attendance, whiteboard, polls, quizzes, breakout rooms, recordings, transcripts/AI summary,
notifications, admin dashboard endpoints. Building these out is the next roadmap stage, following the
same pattern established here: Zod DTOs in `@arutech/validation`, a `PermissionService` capability check,
Prisma access via `PrismaService`, realtime fan-out via `RealtimeBroadcastService` where relevant.
